# 拼豆設計

## 開始前
1. 問使用者兩件事並記住答案（工具不會替你擋，靠你自己把關）：
   - 只用有的顏色嗎？
   - 只用有的數量嗎？
2. `get_design` 看面板（格數、留邊、豆子尺寸）。沒有作品就 `new_design`。
3. `get_palette` 取得所有顏色與庫存數（「庫存0」就是沒有這個顏色）。只用清單裡的色號；使用者要求只用有的顏色時，只挑庫存 > 0 的。
4. 依 `knowledge/scale.md` 決定細節程度。
5. 若要改板子尺寸、豆子尺寸或留邊，用 `set_board`（換豆子尺寸時 `keep` 決定保持格數或實體尺寸；會裁掉豆子時需 `force: true`，先問使用者）。

## 設計流程
1. **大改前先 `snapshot`**。
2. **剪影**：用 `apply_ops` 的 `paste` 一次畫出主體輪廓與大色塊（rows 用字元畫圖），或用 `ellipse`/`polygon`。
   - 主體放在留邊範圍內，並大致置中。
3. **填色**：大面積用 `fill`／`replace_color`。
4. **描邊**：照 `knowledge/outline.md`，通常 `outline {target:"shape", color:"<深色色號>", side:"outer"}`。
5. **明暗**：照 `knowledge/shading.md`，用 `shade` 或 `gradient`，顏色挑選見 `knowledge/color.md`。
6. **細節**：眼睛、腮紅等可用 `recipes/` 的現成圖塊。
7. **檢查**：看 `apply_ops` 回傳的檢查結果或 `run_checks`，依 `knowledge/structure.md` 修正（掛孔放在邊緣往內一格、浮豆、細線）。
8. **自我審查**：`render_preview`（能看圖時）或 `describe_design`（不能看圖時）。至少審一輪：對稱、比例、對比、可讀性。
9. **照庫存把關**（依開始前問到的答案）：
   1. 看檢查結果：只用有的顏色時，「沒有庫存」代表用錯色；只用有的數量時，「庫存不足」代表超量。
   2. 用 `replace_color` 等 op 換成最接近的可用色（同色系優先，見 `knowledge/color.md`），再看一次檢查結果。
   3. 重複到沒有這兩類問題為止。使用者沒限制的面向，缺料提醒只要告訴使用者，不必修。
   4. 使用者中途改主意，同樣用一般 op 改色。

## 做完作品
使用者會在網頁上即時看到你透過 MCP 做的修改（被改到的豆子會跳成一波動畫），所以請優先用少數幾個大的 `apply_ops`（一次一批操作），不要一顆一顆分很多次呼叫，畫面才不會一直閃動。

使用者說「我做完了」「做好了」之類（實際拼完這個作品）時，先跟他確認要扣庫存，再呼叫 `deduct_inventory`（省略 `designId` 就是目前作品）。它會從擁有的顏色扣掉用量（最少到 0），未擁有的色號不動；扣庫存不能 undo，扣錯了請使用者到網頁的庫存頁調整或用 `set_inventory` 修正。把回傳的扣除結果（特別是扣到 0 的色號）告訴使用者。

## 從圖片開始
- 先用 `import_image` 轉一次當底稿，再手修。使用者偏好這種做法，不要整張從空白自己畫（位置比較貼近原圖）。
  - `colors` 限定只用這張圖需要的幾個色號（例如線稿給黑、白和幾個點綴色），避免混進一堆相近的灰；使用者只用有的顏色時，只填庫存 > 0 的色號。
  - `removeBg` 只去掉從外圍連進來的背景，白色角色的身體會保留。背景不只一種顏色（例如白底外還有淡藍天空）時，用 `bgColors` 加上那些顏色（#RRGGBB），去不乾淨再調高 `bgTolerance`（預設 10）。
  - 卡通、線稿圖建議加 `sampling: "dominant"`、`lineBoost: 0.3`、`cleanup: 3`：每格取主要顏色（不會平均出灰邊）、細線不會斷、清掉和周圍相近的雜點（跟周圍差很多的小色塊與深色小點會保留）。照片類的圖不要用 `lineBoost`。
  - `lineBoost` 會把很細的彩色零件（例如帶黑框的吸管）吃成黑色，轉完記得檢查小零件，必要時手補。
  - 圖上有不要的文字或圖案時，用 `exclude` 把那塊（原圖像素座標）當背景略過；只要圖的一部分就用 `crop`。
- 原圖的細線轉換後常會斷開或變成白邊：轉完用 `render_preview` 看一次，把外框補齊。
- 小零件（吸管、杯子等）要加黑邊時，用 `outline {target:"<零件色號>", color:"<描邊色>", side:"outer"}`，不要手算座標一顆顆貼。

## 省 token 原則
- 一次 `apply_ops` 送一整批相關指令，不要一顆一顆畫。
- 能用幾何 op（rect/ellipse/line/polygon/fill）就不要用 paste；paste 只用在不規則形狀。
- 讀圖用 `get_design`（RLE），不要反覆讀；改完看 `apply_ops` 回傳的摘要即可。
- 不要每一步都 `render_preview`，在流程第 8 步集中看。

## 檔案路徑
- `import_image`／`export_png` 的路徑用絕對路徑或 `~/` 開頭。伺服器以 Docker 執行時只能使用 `~/BeadStudio` 裡的檔案（工具說明會寫出實際資料夾）；使用者給的圖片不在裡面時，請他先放進去。

## 錯誤處理
- `apply_ops` 失敗時整批不會套用，照錯誤訊息（含 op 編號）修正後重送整批。

## 學習與更新知識
使用者說「記住」「以後都這樣」，或糾正的是通用規則（不只這一張圖）時：
1. 直接修改對應的 `knowledge/*.md`（新增、修改或刪除規則，避免重複與矛盾）。
2. 涉及數值門檻（留邊、掛孔相鄰數、對比 ΔE、細線長度）時，同步修改專案的 `config/checks.json`，並提醒使用者重新啟動伺服器讓檢查器生效。
3. 在 `CHANGELOG.md` 最上方加一筆：`- YYYY-MM-DD：規則內容（原因／使用者原話）`。
4. 在回覆中用一兩句告訴使用者改了什麼。
